# LexCore｜警察考試智慧備考系統 v3.1.19 — 完整同步模組版

## 這版與前幾版的差異

前幾版是「靜態快照＋同步骨架」。
v0.7 開始才是完整資料管線：

### A. 每日：全國法規資料庫
`node scripts/sync-laws.mjs`

對每一部追蹤法律：
- 抓官方沿革頁
- 找出民國111～115年的修法事件
- 自動解析異動條號與條號區間（例如第10-1～10-3條）
- 抓修法條文與考試必讀條文的現行全文
- 若官方暫時連線失敗，不刪除前次成功資料

### B. 每日：憲法法庭
`node scripts/sync-court.mjs`

自動：
- 掃描111～115年憲判列表
- 發現新判決
- 抓案件日期、字號、案名
- 抓主文／官方摘要／理由
- 自動辨識關聯的刑法、刑訴、憲訴、社維法等法條
- 新判決先產生「機器整理卡」
- 人工編寫的考點卡永遠優先，不會被同步覆蓋

### C. 每週四：立法院
`node scripts/sync-legislative.mjs`

使用官方資料集：
- Dataset 19：法律條文對照表（reviseLaw / activeLaw / description）
- Dataset 373：三讀通過條文&附帶決議資訊

同步範圍只抓民國111～115年可能對應的第10、11屆會期。

## 立法理由的安全機制

最大的風險是：立法院 Dataset 19 同一法條可能有多個委員、黨團或政府提案版本。

所以 v0.7 不會看到 `description` 就直接當正式立法理由。

每筆配對會計算信心分數：
- 法名吻合
- 條號吻合
- 屆期吻合
- `reviseLaw` 與官方現行條文文字相似度
- 是否有說明
- 是否有關係文書

`>= 0.82`：
- 可自動進入前端
- 標示「自動配對 XX%」
- 保存 billNo / docNo / docUrl / 配對證據

`< 0.82`：
- 進 `data/legislative/review-queue.json`
- 不會污染正式立法理由

## 部署

1. 將 ZIP 解壓後整個專案推到 GitHub repository。
2. Repository → Settings → Pages → Deploy from branch → `main` / root。
3. Repository → Actions → 啟用 workflows。
4. 可先手動執行 `Daily official law and court sync`。
5. 成功後 `data/runtime.json` 會被 bot commit 更新。
6. 網站的「同步狀態」頁會直接顯示最新同步結果。

## 本機測試

```bash
npm install
npm test
npm run sync:daily

```

## 失敗保護

- 網站來源暫時掛掉：保留上一次成功資料。
- parser 抓不到內容：標記 error，不把空值覆蓋正確條文。
- 立法理由信心不足：進 review queue。
- runtime 驗證失敗：GitHub Action 直接失敗，不 commit 壞資料。


## v0.8：修正「新修法顯示不完整」

### 真正的主因
全國法規資料庫沿革頁的日期實際常是：
`中華民國一百十五年七月二十二日`

v0.7 的 parser 原本只接受：
`民國 115 年 07 月 22 日`

因此 live sync 可能解析不到沿革事件，而退回舊快照。

v0.8 已改為：
- 同時支援中文數字 ROC 日期與阿拉伯數字
- 以「沿革編號 + 中華民國日期」作事件邊界
- 不會把同一沿革項目內的「施行日期」誤認成另一筆修法
- 同一天如果有兩個不同總統令，兩筆都保留
- 條號解析失敗時，整筆修法事件仍然顯示，不再消失

### 新增「全部修法」頁
把所有追蹤法律民國111～115年的修法跨法規依日期倒序顯示：
- 法規名稱
- 修法日期
- 官方完整事件文字
- 全部解析到的異動條號
- 完整對照／只有現行條文／待同步狀態
- 官方沿革連結

### 條文不再因立法理由尚未配對而看不到
`runtime.json` 新增 `frontend.articleTexts`。
只要全國法規資料庫已抓到現行條文：
- 即使還沒有歷史 Diff
- 即使立法院理由還在 review queue

點條號仍然會直接顯示官方現行條文。

## v1.1：戰情題庫版

### 題庫訓練
- 正式警佐班計分：
  - 單選 20 題，每題 2 分，答錯倒扣 1/3 題分。
  - 複選 20 題，每題 3 分，每個選項判斷正確 +0.6、錯誤 -0.6；整題完全不答為 0。

- 錯題以「選項級」紀錄陷阱類型，不只記整題錯誤。
- 高信心答錯會被弱點演算法提高權重。

弱點不是只看正確率，而是綜合：
- 答錯率
- 正式規則倒扣／得分損失
- 高信心答錯
- 作答速度
- 距離上次作答時間
- 修法／憲判重要度
- 同類陷阱重複錯

每天列出風險最高的 10 個法條／考點。

### 官方歷屆題

- 讀取中央警察大學 113、114、115 年正式試題公告。

- 自動識別「警察法規／刑法及刑事訴訟法／警察勤務／國文與憲法」。
- 解析 1～40 題與 A～E 選項。

單檔 HTML 內建的是「系統診斷題」，明確標示非歷屆原題；部署 GitHub 專案並執行 workflow 後，官方歷屆題才會進入題庫。

- 不寫入 GitHub repository
- 不被 GitHub Actions commit
- 不公開到 GitHub Pages
- 可自行匯出私人備份 JSON

### 去重
以題幹＋選項正規化後產生穩定雜湊 ID。
同一題重複匯出時不會重複新增。

阿摩錯題即使尚未在 LexCore 重新作答，也會成為弱點訊號：
- 同一法條匯入錯題越多，風險提高。
- 重新作答後，再加入正式倒扣、信心度、速度與選項級陷阱。
- 不會把「匯入錯題」偽造成正式模考失分，因此正式平均分率不被歷史錯題扭曲。

### 解析限制
阿摩匯出頁面格式若改版，泛用解析器可能有部分題目抓不到。
系統會顯示解析成功率、未辨識答案、未辨識法條與重複題數，而不是亂猜資料。
若詳解圖片是相對路徑而非內嵌／絕對網址，v1.2 先保留文字詳解，不保證圖片可離線還原。

## v1.4：阿摩2026 HTML答案解析修正

依實際「常錯匯出2026_08_23」HTML校正 parser。

### 根因
阿摩匯出格式沒有把正確答案寫成：
`答案：B`

而是在每個 `.item-row` 左側紅色答案欄：
- 單選：`( B )`
- 複選：`( A,B,C )`

v1.2/v1.3 的泛用文字 parser 因此無法辨識。

### v1.4 修正
- HTML 優先偵測 `.item-row`
- 從 `w-20 ... text-red-600` 答案欄抓正確答案
- 支援 A～E 單選及逗號分隔複選
- 讀取 `答對 xx%` 作為阿摩歷史正確率
- 題幹直接取 `.item-body` 第一個題目 `<b>`，避免詳解內容污染選項
- 詳解從其餘 `.item-body` 內容擷取
- 原本泛用 HTML parser 保留作 fallback

### 已匯入舊資料可直接修復
重新匯入同一份檔案時，如果同一題已存在但缺少：
- 正確答案
- 詳解
- 法規／條號
- 阿摩答對率

會標成「可修復」並覆蓋補齊，不需要先清空 IndexedDB。

## v2.0：學習引擎版

### 1. 掌握度 0–100
掌握度與考試重要度拆開計算。

掌握度主要來源：
- 最近 10 次實際得分（越近權重越高）
- 答對穩定度
- 信心度
- 高信心答錯
- 距離上次作答的遺忘時間
- 阿摩匯入錯題訊號
- 使用者手動「再複習」

重要度不直接改變 mastery，而只用在今日任務 priority。

### 2. 間隔複習
localStorage:
`lexcore-spaced-review-v20`

作答品質 quality：
- 高信心答對 = 5
- 普通信心答對 = 4
- 猜對 = 3
- 低信心答錯 = 2
- 普通信心答錯 = 1
- 高信心答錯 = 0

基礎間隔：
1 → 3 → 7 → 14 → 30 → 60 → 90 天。

答錯時重置為 1 天；高品質連續答對後逐步拉長。

### 3. 今日學習任務
每日任務排序：
1. 已到期複習
2. 手動「再複習」
3. 掌握度 < 60 的弱點
4. ★★★★～★★★★★重要修法
5. 綜合優先度

使用者可設定：
20 / 30 / 45 / 60 / 90 分鐘。

每項預估 5 分鐘，依目標時間自動控制任務數。
